# VCC 2026 研发工作台

更新：2026-09-27。本次建立研究机制与历史证据索引，没有启动训练；下列候选和计划均不是已实现结果。
执行规则见 [AGENTS.md](../AGENTS.md)。本文件只维护跨实验的方法空间、证据和下一步，单次方案与结果继续使用各 Experiment 的 PLAN/config/REPORT。

## 1. 核心研究思路

任务是学习 `q(Y | B_c, p)`：`B_c` 是未知背景的 NTC 细胞群，`p` 是扰动靶点。
目标背景仅暴露未扰动表达，模型须迁移其他背景的扰动知识；A/B/C 是开发阶段，D/E/F 是另三个最终背景。
当前官方提交要求每个背景、每个靶点生成 400 个细胞，覆盖固定 18,533 基因，输出非负有限整数 counts。
这些约束来自 [Arc 2026 任务说明](https://arcinstitute.org/news/virtual-cell-challenge-2026) 和 [官方提交说明](https://vcc-cli-wiki.virtualcellchallenge.org/#submission-requirements-2026)，具体执行以锁定的数据包和规则版本为准。

[分享对话](https://chatgpt.com/share/6ab9c3e3-56cc-83e9-bbef-b1f196a8e83c) 提供的研究出发点是：有限独立观测下，数据可信度、结构先验和表示决定哪些映射值得学习。
本项目将它落实为三个可以分别验证的问题：NTC 是否准确描述背景；跨背景响应能共享多少、如何修正；响应如何变成合理的单细胞分布。

一个候选结构是：

```text
NTC population → 背景表示 ─┐
靶点/基因/外部知识表示 ────┼→ 共享响应 + 背景修正 → 条件计数生成 → 评分
来源背景的实测响应 ────────┘
```

这是方法假设，不是唯一架构。`Y = Baseline + Δ` 必须注明在 counts、CPM、log 表达还是 latent 空间使用；log2FC 需经变换和组成约束生成 counts。
未配对 NTC 与扰动细胞不能直接作为逐细胞因果配对。功能模块可降低自由度，但应保留基因特异残差，并检验是否丢失方向或弱效应。
相关候选机制已在 [初始建模思路](ideas/initialized-thought.md) 与 [响应异质性变量](ideas/variations.md) 中展开；其中状态代理不等于实际测得的机制变量。

## 2. 方法空间：九轴覆盖检查表

每次只从有证据关联的问题选择少量候选。表中“可检验问题”是研究建议，不表示对应配置已经实现。
在 PLAN/config 用可读名称组成 `method`；精确参数、数据和版本仍由实际 config 定义，避免维护另一份配置注册表。

| 轴 | 管什么 | 首选对照与候选 | 可检验问题 |
|---|---|---|---|
| T：任务 | 监督量与分解 | 直接表达、CPM Δ、log2FC；共享响应 + 背景残差；均值 + 分布 | 分解是否减少需要从少量背景学习的自由度？标签尺度与生成变换须一并披露 |
| D：数据 | 来源、有效性、QC、权重 | 有效性清理后的固定数据；单项额外 QC；guide 可靠性或 context/target 平衡；单来源增删 | 收益来自质量、覆盖还是样本数量？固定评分 reference，按来源和效应强度分层 |
| R：表示 | NTC、靶点、readout 的信息 | NTC 统计/PCA；均值 + 方差；等维模块；冻结预训练表示；集合编码器；连续来源响应 | 是否提供新增信息？匹配下游容量，审计表示拟合与来源标签边界 |
| A：架构 | 信息如何映射为响应 | 直接响应转移、线性/低秩、现有 XGBoost、小 MLP；再考虑条件生成或更大网络 | 简单模型的剩余误差是否真由表达能力不足造成？ |
| L：目标 | 拟合与约束 | 当前加权回归；稳健损失；方向/幅度项；计数或分布目标 | 训练误差改善能否转成留出指标改善？不直接混加量纲不同的指标 |
| O：优化 | 训练过程 | 收敛诊断、采样覆盖、正则化、学习率、训练长度、分阶段训练 | 是否欠训练或过拟合？比较预先约定的训练/调参预算，并记录实际成本 |
| V：验证 | 衡量与选模规则 | 固定版本的本地跨背景基准；分别标识 context、perturbation、joint、dataset OOD | 能否区分任务泛化与来源/技术混杂？本轴作为协议固定，变化后建立新对照 |
| I：推理 | counts 与分布输出 | 固定 NTC 模板生成；均值/总量/方差校准；后续条件生成或集成 | 固定 checkpoint 时，收益来自响应保真还是采样分布？ |
| G：迁移 | 跨背景适配机制 | 共享响应；背景加权检索/收缩；context gating；仅 NTC 的适配 | 何时共享、何时回退？区分训练已见和全局未见靶点 |

G 会涉及 T/R/A/L 等实现，D 的权重也可能通过 L/O 实现。每项比较选一个主要问题，列出全部实际差异；九个字母不是九个统计独立变量。

先验使用统一的短描述，不增加第十个搜索轴：

| 先验假设 | 注入位置 | 对照与失效信号 |
|---|---|---|
| 响应含可迁移共享部分 | T/G 的共享响应与收缩 | 直接迁移 vs 背景修正；来源方向冲突、未见靶点或错误来源加权时可能失效 |
| 响应由低维程序组织 | R/A 的模块或低秩表示 | 等维 PCA/NMF、随机模块及基因残差；同压缩率下无增益则不能归功于生物模块 |
| 已知图关系携带预测信息 | R/A/L 的图特征/约束 | 无图、真实图、匹配节点/边数及度分布的随机图；覆盖率高但无留出增益不支持该实现 |
| 预训练表示含可迁移状态 | R 的冻结编码器 | 简单统计/等维表示；固定模型版本、基因映射和预训练数据范围，排查监督重叠 |
| 指定噪声模型适合细胞分布 | I/L 的计数或残差模型 | 固定均值后的零率、方差、深度和伪 DE；不能用方差调节所得分数证明均值机制更好 |

记录先验的来源版本、适用条件、预期现象与反例；真实知识、随机结构和压缩作用分别归因。需要随机图时，图随机种子与训练/生成种子分开记录。

## 3. 最小归因单元

### 一个问题，一张比较卡

在相关 PLAN 中写下比较卡，config 保存实际生效条件；多臂比较指定一个 PLAN 为主卡，其他 PLAN 引用它并补充本臂差异。
`comparison_id` 连接一组比较，`control_refs` 表示科学对照，来源字段表示数据、权重或产物复用。二者不能互相替代；读取历史记录时保留其原字段和身份。
比较关系由这些引用形成图，无需另建 DAG 文件或人工 run registry。

```yaml
# PLAN 中的模板；尖括号必须在执行前替换。不是可直接启动的配置。
comparison_id: <例如 CMP-D-QC-01>
purpose: screen                 # screen / confirm / interaction / integrate
hypothesis: <什么因素通过什么机制改善哪个任务子集>
control_refs: [<对照的精确 config 路径与 W&B 身份>]
changed_factors: [<实际 from/to；包括必要的联动变化>]
method: {T: <标签>, D: <标签>, R: <标签>, A: <标签>, L: <标签>, O: <标签>, V: <标签>, I: <标签>, G: <标签>}
prior: <假设；注入位置；来源版本；消融；失效条件，或 none>
benchmark_ref: <对照 config 中完整评估设置的固定 Git/哈希引用>
frozen_conditions: <数据、split、特征、模型、训练、生成、评估中保持相同的部分>
pairing: <配对 context/fold、数据抽样、训练及生成 seed；每类种子分别记录>
budget_and_end: <每臂训练结束条件、检查点选择和调参机会；预计成本>
decision_rule:
  primary: <主指标/任务子集；实际意义阈值 δ>
  guardrails: <其他指标或关键子群容许的最大退步及理由>
  support: <达到怎样的效应、稳定性和独立验证范围后采用>
  against: <何种充分精度的结果否定当前实现的预期>
  inconclusive: <波动或支持不足时补哪一个对照/背景/重复>
```

预设 δ 与退步边界依据对照波动和实际意义选择，不全项目硬设“涨 0.01 就成功”。缺少波动估计时先做对照重复，锁定判据后再评候选。
探索后形成的新假设登记为下一次比较，不能回写成事先预测。

### 公平比较与不确定性

- 筛选用一个预设种子或较小的**完整**方案发现线索；确认使用事先选定的配对重复与验证范围。三个训练种子是可用起点，不是自动获得确认的门槛；确定性方法不用虚造训练重复。
- 单因素比较匹配数据抽样、训练或资源预算以及选模机会，写明匹配哪一种。不同架构不一定能同时匹配轮数、参数量和算力；剩余差异限制结论，必要时补等预算对照。
- 在相同评估条件下计算每个匹配单位的 `d = S(candidate) - S(control)`。Overall 和 normalized 分项越高越好；raw MSE/NMAE 越低越好，其余 raw 指标方向见固定 scorer。保留原始单位，避免符号混淆。
- 汇报均值/中位数、逐背景点、最差背景和有效靶点数。区间或标准差注明是训练随机性、生成随机性、靶点抽样还是背景变异；不同来源的波动不可互换。单背景的靶点配对仅支持该背景，不外推背景总体；极少背景不提供虚假精确的跨背景置信度。
- 指标存在全 panel 排名、真实侧 DE gate 和共同 anchors 时，子集 raw 指标可作诊断；子集 Overall 或 bootstrap 区间须遵循 scorer 聚合依赖重新计算，不能任意平均每细胞误差冒充官方结果。报告无法评估项及原因，不能填零或只留候选表现好的靶点。
- 多次搜索使用同一开发集会产生选择偏差。报告搜索次数/候选数；确认使用预先保留且未用于选择的评估范围，若没有则明确只有开发证据。H1 和已用于反馈的 A/B/C 不能重新命名为独立测试。

交互比较只需 `Base/A/B/A+B` 四臂，在共同协议上计算 `S(A+B)-S(A)-S(B)+S(Base)`。
优先检查有证据的因素，也允许有机制理由的少量“单独无效但可能协同”的组合；不默认展开大规模析因设计。
集成允许多因素，收益只归于整体；事后解释单模块贡献须补消融。

## 4. 评价协议与小样本数据边界

`benchmark_ref` 指向配置里完整、不可变的评估定义：数据版本和物理身份划分、任务/基因面板与缺测 mask、输入/评分 NTC、参考细胞及抽样、预处理/CPM 分母、scorer commit/config、baseline 构造及 target exclusion、anchors、生成数量和评分聚合方式。
沿用项目已有 `evaluation_protocol` 字段；同名协议内容改变须新版本。训练数据是 D 比较的因素时可以改变，评分 reference/支持范围保持固定。I 比较改变生成算法时冻结其余评分条件，并将生成差异登记为因素。

新本地基准隔离输入与评分 NTC；需要更换输入池时同步重算相关特征、预测和 anchors，不能仅替换 scorer 的 control 或缩放旧分数。
正确性修复可能使历史输出不再适合作对照，此时重新建立有效对照，不要求故意重跑已知错误。
固定 [cell-eval2 指标文档](https://github.com/ArcInstitute/cell-eval2/blob/5e64833518a6603a0301cbe28185d49c30f4a986/docs/vcc2026_metrics/vcc2026-metrics.md) 只是协议的一部分；本地分数与线上 panel/anchor 身份不同，绝对值不换算。

| 评估问题 | 划分/用途 | 结论范围 |
|---|---|---|
| 拟合是否正常 | 已见背景/靶点，物理细胞不重复 | ID 检查，不证明迁移 |
| 背景迁移 | 留出背景仅暴露输入 NTC，靶点在训练其他背景出现 | context-OOD |
| 靶点迁移 | 训练全部来源中移除指定靶点扰动标签 | perturbation-OOD；保留靶点静态知识的范围需声明 |
| 联合迁移 | 同时留出背景和全训练靶点标签 | joint-OOD |
| 来源迁移 | 留出研究/平台 | dataset-OOD；背景与研究重合时不能分离两者影响 |

这些是结论分类，不要求每个 Experiment 执行所有划分；已有用户约定的 PLAN 范围继续有效。新增确认范围需在新方案中说明。
所有使用扰动标签拟合的响应特征、表示、模块和检索库遵守同一留出边界；训练样本使用其他背景响应时也排除自身背景。
单独比较“seen targets 分数”和“unseen targets 分数”会混入任务难度，主要看各自组内候选相对对照的变化。

数据探索优先问“新增了多少独立、可用的背景×靶点支持”，并登记来源、干预类型/强度、时间、平台、guide 和匹配 NTC。
正确性清理覆盖 counts、身份、重复、基因映射及测量 mask；额外 QC 是研究因素，需报告剔除原因、覆盖变化和响应强度分层。
可增加同数量随机剔除对照，区分筛选质量与样本量变化；按真实扰动响应强弱删样本会改变任务分布，应显式命名为数据选择。
观察性表达用于表示学习不自动成为 NTC 或 CRISPRi 监督数据。对未测量基因保留 mask，对无显著性与零响应保持不同语义。

## 5. Git、W&B 与证据各管一件事

| 位置 | 唯一职责 |
|---|---|
| 本文件 | 候选方法、跨实验证据摘要、下一步队列 |
| Experiment PLAN | 比较卡与执行前判据；主卡只维护一份 |
| 实际 config + Git commit/lock | 全部生效条件、`comparison_id`、`purpose`、方法标签、对照与来源、完整评估引用 |
| metrics / 预测 / checkpoint + W&B | 数值、曲线、资源、执行状态与版本化结果；保持 AGENTS 规定的身份 |
| Experiment REPORT | 完整比较、效应、不确定性、失败原因、局限和证据链接 |

新配置将比较字段随实际配置记录到 W&B，按 `config.comparison_id` 筛选；身份与 group 遵守 AGENTS，历史记录不重写。
本次只定义约定，没有新增自动登记脚本或改造已有入口。后续正式实现时在所属流程接入，不能声称旧 run 已自动记录新字段。
W&B 离线时用本地 config/metrics 形成证据并注明待同步，网络恢复后补精确链接。
证据摘要链接 REPORT、具体执行身份及固定 Artifact 版本；不另抄全量曲线。历史记录缺少预注册或新字段时如实标注，不能追补成事先设计。

证据采用以下状态，与执行的 completed/failed 独立：

| 状态 | 含义 | 默认动作 |
|---|---|---|
| 待检验 | 只有假设，没有有效比较 | 设计最小比较 |
| 线索 | 筛选、单背景或单次有效比较的信号 | 配对确认或补关键对照 |
| 支持 | 达到预设判据，且注明独立验证和适用范围 | 在该范围采用；扩展范围另验证 |
| 未支持 | 足够精度/有效执行下，当前实现未达预设收益或明确变差 | 搁置当前实现，写明重新打开的条件 |
| 证据不足 | 缺对照、波动大、协议不匹配或无法隔离因素 | 补能区分解释的证据；不当作无效 |

效果依赖 context/覆盖时在结论中写条件，不强迫压成一个总体胜负。失败仅记录执行失败与原因。

## 7. 下一步队列（至多三个问题）

这是实施建议，尚未创建执行身份或 W&B 记录；[exp008](../experiments/exp008/PLAN.md) 中已有用户约定的 H1 单背景、QC 与训练方案继续有效。

|---|---|---|---|
| 1. 当前有效基准下谁是可信对照？ | 在同一新协议登记零响应/NTC、直接同靶点转移、当前简单模型；输入/评分 NTC 隔离，共用 reference、基因轴、anchors 和生成约定。固定旧权重的重评标为协议诊断；若新训练输入会影响模型有效性，则另行完整训练，不能混称 | 直接迁移更好：保留为主对照，研究背景修正；模型更好：定位优势子群；排序随协议/抽样不稳：先查评分和生成 | 影响高，当前缺少可比证据，会阻塞全部后续归因；评分也计入成本 |
| 2. 额外 QC 是否改善有效监督？ | 有效性修复后，在固定轴、NTC 和模型训练预算上，仅比较基础 QC 与一种额外 QC/可靠性权重；保留评估 reference，报告保留率和效应分层，必要时补等量随机剔除 | 稳定改善且覆盖可接受：采用并确认；仅强效应占比改变：限缩结论；无实用增益：保留基础处理 | 影响高、不确定性高、改动相对局部。exp008 若多项同时变化，仅作为整包结果，归因另登记对照 |
| 3. 共享响应缺的是背景适配还是表示？ | 在问题 1 的固定对照上，先二选一：来源背景加权/收缩，或加入一种 NTC 状态表示；固定响应源、下游容量和生成器。按已见/未见靶点、来源支持与方向冲突分层 | 仅已见靶点有效：保留有支持时的分支；只降训练 loss：检查过拟合；证据指向结构信息不足时，再做真实/随机/无先验匹配比较 | 有 E02/E03 线索，比直接升级大型生成架构更能区分现有失败解释 |
